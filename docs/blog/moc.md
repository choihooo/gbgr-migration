# Electron 웹뷰 앱을 Tauri Native UI로 마이그레이션하기: 시리즈 목차 초안

이 문서는 블로그 시리즈 전체 흐름을 관리하기 위한 초안 목차다. 각 글은 레거시 분석, 설계 판단, 구현, 테스트, 회고가 자연스럽게 이어지도록 구성한다.

## 시리즈 목차

1. 왜 Electron 웹뷰 앱을 Tauri Native UI로 마이그레이션하는가
기존 Electron 웹뷰 구조의 한계와, 이번 전환에서 무엇을 바꾸고 무엇을 바꾸지 않을지 정리한다.

2. 레거시 `src` 구조를 어떻게 읽고 분해할 것인가
기존 앱의 화면, 라우팅, 상태, 인증 흐름을 어떤 관점으로 분석해야 하는지 정리한다.

3. `migration` 앱의 기본 골격은 어떻게 설계했는가
Tauri + React + React Router + Zustand + TanStack Query 조합을 왜 선택했고, 어떤 역할로 나눴는지 설명한다.

4. React Router 기반 라우팅을 어떻게 다시 세웠는가
웹뷰 중심 이동 흐름을 앱 내부 라우팅 구조로 바꾸는 과정과 기준을 다룬다.

5. 인증 도메인을 Tauri 환경에 맞게 어떻게 옮겼는가
인증 API, 세션 처리, 딥링크 진입 정보, 클라이언트 저장소를 새 런타임에 맞게 재구성한 과정을 정리한다.

6. `localStorage` 기반 저장소와 앱 상태를 어떻게 정리했는가
브라우저 저장소 의존 로직을 테스트 가능한 구조로 분리하고 상태 흐름을 안정화한 방법을 설명한다.

7. 공통 UI 컴포넌트를 어떻게 재구성했는가
스타일은 유지하면서도 재사용 가능한 컴포넌트 구조로 바꾼 기준과 방법을 다룬다.

8. 레이아웃 설정과 화면 구조를 어떻게 맞췄는가
기존 UI 스타일을 바꾸지 않고 레이아웃 설정과 화면 단위를 새 구조에 이식한 과정을 정리한다.

9. 테스트 환경을 어떻게 구성해 회귀를 막았는가
Vitest, 라우터 테스트 유틸, 스토리지 목킹을 활용해 마이그레이션 중 회귀를 어떻게 관리했는지 설명한다.

10. 실제 화면 하나를 끝까지 마이그레이션해보기
레거시 화면 하나를 골라 분석, 분해, 컴포넌트화, 상태 연결, 테스트까지 전 과정을 보여준다.

11. 마이그레이션 중 만난 문제와 판단 기록
예상과 달랐던 지점, 구조적 제약, 구현 중 선택한 우회 방법과 판단 근거를 공유한다.

12. 이번 전환에서 남은 과제와 다음 단계
현재까지 옮긴 범위와 아직 남은 영역, 이후 어떤 순서로 확장할지 정리한다.

## 작성 원칙 메모

- 모든 문서는 한글로 작성한다.
- UI 스타일은 절대 바꾸지 않는다.
- 레거시 개선 포인트는 확인 후 반영한다.
- 각 글은 가능하면 문제 상황, 레거시 확인 사항, 설계 결정, 구현 포인트, 테스트, 남은 과제 순으로 정리한다.
