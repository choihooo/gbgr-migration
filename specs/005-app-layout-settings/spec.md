# Feature Specification: 앱 레이아웃 및 설정 시스템

**Feature Branch**: `005-app-layout-settings`
**Created**: 2026-04-14
**Status**: Draft
**Input**: 앱 레이아웃 뼈대(헤더, 탭 네비게이션)와 설정 시스템(설정 모달, 알림 설정, 테마 전환) 구현. 레거시 앱의 Layout, Header, MainHeader, SettingsModal, NotificationModal 컴포넌트를 마이그레이션 프로젝트로 포팅.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 앱 레이아웃 셸 (Priority: P1)

사용자가 앱을 실행하면 일관된 레이아웃(상단 고정 헤더 + 콘텐츠 영역)을 본다. 인증 완료 후 모든 페이지가 동일한 레이아웃 구조 내에서 렌더링된다. 헤더에는 로고(심볼 + 텍스트)와 테마 전환 토글이 표시된다.

**Why this priority**: 레이아웃 셸은 모든 인증 후 페이지의 기반이 되며, 헤더와 콘텐츠 영역의 일관된 구조 없이는 다른 기능(네비게이션, 설정 등)을 배치할 수 없다.

**Independent Test**: 레이아웃 셸만 렌더링하여 헤더가 상단 고정되고 로고와 테마 토글이 표시되며, 콘텐츠 영역에 임의의 자식 요소가 정상적으로 렌더링되는지 확인.

**Acceptance Scenarios**:

1. **Given** 사용자가 인증을 완료한 상태에서, **When** 앱의 메인 페이지에 진입하면, **Then** 상단에 고정된 헤더(로고 + 테마 토글)와 그 아래 콘텐츠 영역이 표시된다.
2. **Given** 레이아웃이 렌더링된 상태에서, **When** 콘텐츠 영역이 헤더 높이만큼 상단 패딩을 가지면, **Then** 콘텐츠가 헤더에 가려지지 않고 정상적으로 표시된다.
3. **Given** 헤더가 렌더링된 상태에서, **When** 화면 너비가 변경되면, **Then** 헤더가 전체 너비를 유지하며 반응형으로 동작한다.

---

### User Story 2 - 대시보드 헤더 및 탭 네비게이션 (Priority: P1)

사용자가 대시보드 페이지에서 둥근 알약 모양의 탭 네비게이션 바를 통해 대시보드, 설정, 리포트, 리뷰 탭 간 전환할 수 있다. 좌측에는 로고가, 우측에는 테마 전환 토글과 알림 버튼이 표시된다.

**Why this priority**: 대시보드는 인증 후 사용자가 가장 먼저 마주하는 핵심 페이지이며, 탭 네비게이션은 주요 기능 간 이동의 핵심 인터랙션이다.

**Independent Test**: 대시보드 헤더 컴포넌트만 렌더링하여 로고, 탭 네비게이션, 테마 토글, 알림 버튼이 레거시와 동일한 레이아웃으로 표시되는지 확인.

**Acceptance Scenarios**:

1. **Given** 대시보드 헤더가 렌더링되면, **When** 사용자가 탭을 클릭하면, **Then** 해당 탭이 활성화되고 시각적으로 활성 상태로 표시된다.
2. **Given** 대시보드 헤더가 렌더링되면, **When** 화면을 확인하면, **Then** 좌측에 로고, 중앙에 알약 모양 탭 네비게이션, 우측에 테마 토글과 알림 버튼이 배치된다.
3. **Given** 알림 버튼이 표시된 상태에서, **When** 사용자가 알림 버튼을 클릭하면, **Then** 알림 설정 모달이 열린다.

---

### User Story 3 - 테마 전환 (Priority: P1)

사용자가 헤더의 테마 토글 스위치를 통해 라이트/다크 모드를 전환할 수 있다. 테마 설정은 로컬에 저장되어 앱 재시작 시에도 유지된다.

**Why this priority**: 테마 전환은 헤더의 핵심 기능이며, 사용자 경험에 직접적인 영향을 미친다. 이미 구현된 ToggleSwitch 컴포넌트를 활용할 수 있다.

**Independent Test**: 테마 토글만 클릭하여 라이트/다크 모드 전환 시 CSS 변수가 올바르게 변경되고, 페이지 새로고침 후에도 설정이 유지되는지 확인.

**Acceptance Scenarios**:

1. **Given** 현재 라이트 모드인 상태에서, **When** 사용자가 테마 토글을 클릭하면, **Then** 다크 모드로 전환되고 모든 UI 요소의 색상이 변경된다.
2. **Given** 테마를 변경한 상태에서, **When** 앱을 재시작하면, **Then** 이전에 설정한 테마가 유지된다.
3. **Given** 테마 전환 시, **When** 시스템 OS 테마 설정이 변경되면, **Then** 사용자가 수동으로 테마를 설정하지 않은 경우 시스템 테마를 따른다.

---

### User Story 4 - 설정 모달 (Priority: P2)

사용자가 대시보드 설정 탭 또는 설정 진입점을 통해 설정 모달을 열 수 있다. 설정 모달에는 OS 자동 시작 토글, 로그아웃, 회원 탈퇴, 캘리브레이션 초기화 옵션이 포함된다.

**Why this priority**: 설정 모달은 핵심 사용자 기능(로그아웃, 탈퇴)을 제공하지만, 레이아웃 셸과 네비게이션 이후에 구현되어야 한다.

**Independent Test**: 설정 모달만 열고 닫아 각 설정 항목(자동 시작 토글, 로그아웃 버튼, 탈퇴 버튼, 캘리브레이션 초기화)이 레거시와 동일하게 표시되고 동작하는지 확인.

**Acceptance Scenarios**:

1. **Given** 설정 모달이 열리면, **When** 콘텐츠를 확인하면, **Then** OS 자동 시작 토글, 로그아웃, 회원 탈퇴, 캘리브레이션 초기화 항목이 순서대로 표시된다.
2. **Given** OS 자동 시작 토글이 표시된 상태에서, **When** 사용자가 토글을 전환하면, **Then** OS 시작 시 앱 자동 실행 설정이 변경된다.
3. **Given** 설정 모달이 열린 상태에서, **When** 사용자가 오버레이를 클릭하거나 ESC를 누르면, **Then** 모달이 닫힌다.
4. **Given** 로그아웃 버튼이 표시된 상태에서, **When** 사용자가 클릭하면, **Then** 로그아웃 처리 후 로그인 페이지로 이동한다.

---

### User Story 5 - 알림 설정 모달 (Priority: P2)

사용자가 알림 버튼을 통해 알림 설정 모달을 열 수 있다. 알림 허용 토글, 스트레칭 알림 주기, 거북목 경고 주기를 설정할 수 있다.

**Why this priority**: 알림 설정은 건강 관련 핵심 기능이지만, 대시보드 헤더의 알림 버튼 구현 이후에 가능하다.

**Independent Test**: 알림 설정 모달만 열어 각 설정 항목(알림 허용 토글, 스트레칭 주기, 거북목 주기)이 레거시와 동일하게 표시되고, 시간 편집 인터랙션이 정상 동작하는지 확인.

**Acceptance Scenarios**:

1. **Given** 알림 설정 모달이 열리면, **When** 콘텐츠를 확인하면, **Then** 알림 허용 토글, 스트레칭 주기 설정, 거북목 경고 주기 설정이 표시된다.
2. **Given** 알림 허용 토글이 OFF 상태에서, **When** 사용자가 토글을 ON으로 전환하면, **Then** 알림 설정 항목들이 활성화된다.
3. **Given** 시간 설정 영역에서, **When** 사용자가 +/- 버튼으로 시간을 조절하면, **Then** 시간 값이 증가/감소하고 시각적으로 업데이트된다.
4. **Given** 시간 설정 영역에서, **When** 사용자가 시간 값을 직접 인라인 편집하면, **Then** 입력한 값으로 업데이트된다.

---

### Edge Cases

- 레이아웃 전환 시(인증 페이지 → 대시보드) 헤더가 깜빡이지 않고 부드럽게 전환되는가?
- OS 자동 시작 기능이 Tauri에서 지원되지 않는 환경에서 적절한 fallback이 있는가?
- 테마 전환 시 이미지나 비디오 에셋(LoadingSpinner 등)이 올바르게 표시되는가?
- 설정 모달과 알림 모달이 동시에 열리는 것을 방지하는가?
- 알림 주기 시간 편집 시 음수나 비정상적으로 큰 값이 입력되는 것을 방지하는가?
- 로그아웃/탈퇴 시 현재 열려 있는 모든 모달이 정상적으로 닫히는가?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 상단 고정 헤더와 콘텐츠 영역으로 구성된 레이아웃 셸을 제공해야 한다.
- **FR-002**: 헤더에는 로고(심볼 + 텍스트)와 테마 전환 토글이 포함되어야 한다.
- **FR-003**: 대시보드 헤더는 알약 모양 탭 네비게이션(대시보드, 설정, 리포트, 리뷰)을 제공해야 한다.
- **FR-004**: 대시보드 헤더 우측에 테마 전환 토글과 알림 버튼이 배치되어야 한다.
- **FR-005**: 테마 전환 시 라이트/다크 모드가 즉시 적용되어야 한다.
- **FR-006**: 테마 설정은 로컬 저장소에 저장되어 앱 재시작 시 유지되어야 한다.
- **FR-007**: 시스템 테마(OS 설정)를 기본값으로 감지할 수 있어야 한다.
- **FR-008**: 설정 모달은 OS 자동 시작 토글, 로그아웃, 회원 탈퇴, 캘리브레이션 초기화 항목을 포함해야 한다.
- **FR-009**: 설정 모달의 OS 자동 시작은 Tauri 네이티브 API를 통해 OS 시작 프로그램으로 등록/해제해야 한다.
- **FR-010**: 로그아웃 시 인증 상태를 초기화하고 로그인 페이지로 이동해야 한다.
- **FR-011**: 알림 설정 모달은 알림 허용 토글, 스트레칭 주기, 거북목 경고 주기를 포함해야 한다.
- **FR-012**: 시간 주기 편집은 +/- 버튼과 인라인 직접 입력을 모두 지원해야 한다.
- **FR-013**: 알림 설정은 로컬 상태로 관리되어야 한다.
- **FR-014**: 모든 모달은 004에서 구현된 Modal 컴포넌트를 재사용해야 한다.
- **FR-015**: 테마 전환 토글은 sun/moon 아이콘이 포함된 독립 ThemeToggleSwitch 컴포넌트로 구현해야 한다.
- **FR-016**: 레이아웃 및 모든 컴포넌트는 라이트/다크 테마를 지원해야 한다.

### Key Entities

- **ThemePreference**: 사용자의 테마 설정 상태. light, dark, system 세 가지 값. 로컬 저장소에 영속화.
- **AppLayout**: 앱의 레이아웃 구조. 인증 전(헤더 없음)과 인증 후(고정 헤더 + 콘텐츠) 두 가지 모드.
- **NavigationTab**: 대시보드 내 탭 네비게이션 항목. 대시보드, 설정, 리포트, 리뷰.
- **SettingsOption**: 설정 모달의 개별 설정 항목. 자동 시작(토글), 로그아웃(버튼), 회원 탈퇴(버튼), 캘리브레이션 초기화(버튼).
- **NotificationSettings**: 알림 설정 상태. 알림 허용 여부, 스트레칭 주기(분), 거북목 경고 주기(분).
- **TimeEditor**: 시간 편집 인터랙션 상태. 현재 값, 최소/최대 범위, 증감 단위.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 마이그레이션된 레이아웃이 레거시 앱과 동일한 헤더 높이, 로고 배치, 콘텐츠 영역 구조를 갖는다.
- **SC-002**: 테마 전환 시 100ms 이내에 모든 UI 요소의 색상이 전환된다.
- **SC-003**: 각 탭 전환 시 해당 콘텐츠가 즉시 렌더링된다.
- **SC-004**: 설정 모달과 알림 모달이 각각 독립적으로 열고 닫히며, 레거시와 동일한 레이아웃을 갖는다.
- **SC-005**: 앱 재시작 후에도 테마 설정과 알림 설정이 유지된다.

## Assumptions

- 004-shared-ui-components에서 구현된 Modal, ToggleSwitch, NotificationToggleSwitch 컴포넌트를 재사용한다.
- 003-auth-domain-implementation에서 구현된 인증 상태 관리(useAuthUserStore 등)를 활용한다.
- 레거시의 `window.electronAPI.startup`은 Tauri의 자동 시작 API(`tauri-plugin-autostart`)로 대체한다.
- 레거시의 `window.electronAPI.notification`은 Tauri 알림 플러그인 또는 웹 알림 API로 대체한다.
- 로고 에셋(Symbol, Logo)은 레거시에서 동일하게 복사하여 사용한다.
- 캘리브레이션 초기화 기능은 캘리브레이션 관련 스펙에서 상세 구현하며, 이 스펙에서는 UI 버튼 배치까지만 다룬다.
- 리포트와 리뷰 탭은 별도 스펙에서 구현하며, 이 스펙에서는 탭 네비게이션 구조만 제공한다.
- FSD 아키텍처를 따라 레이아웃은 `app/` 레이어, 기능별 모달은 `features/` 레이어에 배치한다.
