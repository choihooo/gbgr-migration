# Feature Specification: 온보딩/보정 도메인 이관

**Feature Branch**: `007-onboarding-calibration`
**Created**: 2026-04-14
**Status**: Draft
**Input**: User description: "007 온보딩/보정 도메인 - 온보딩 시작/진행/완료 화면, 자세 보정 흐름, 보정 상태 판별 로직"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 온보딩 소개 단계를 밟는다 (Priority: P1)

처음 앱을 시작한 사용자는 로그인 직후 온보딩 소개 화면에 진입해 앱의 핵심 기능(자세 분석, 실시간 위젯, 대시보드, 알림, 게임)을 5단계 슬라이드로 안내받고, 카메라 권한 안내 화면으로 자연스럽게 이동할 수 있어야 한다.

**Why this priority**: 온보딩 소개는 신규 사용자가 앱에 처음 진입했을 때 마주하는 첫 화면이다. 이 단계가 동작하지 않으면 이후 보정 흐름으로 진입할 수 없으므로 최우선으로 이관해야 한다.

**Independent Test**: 로그인 후 `/onboarding/init`에 진입해 5단계 슬라이드 내용과 네비게이션이 레거시와 동일하게 표시되는지, 마지막 단계에서 다음 화면으로 이동하는지 확인하면 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 처음 로그인한 사용자가 보정이 필요한 상태일 때, **When** `/onboarding/init`에 진입하면, **Then** 5단계 소개 슬라이드(자세 분석, 실시간 위젯, 대시보드, 알림, 게임)가 레거시와 동일한 내용과 순서로 표시되어야 한다.
2. **Given** 소개 슬라이드의 각 단계가 표시될 때, **When** 사용자가 단계를 넘기면, **Then** 진행 표시자와 단계 전환 애니메이션이 레거시와 동일하게 동작해야 한다.
3. **Given** 마지막 단계까지 모두 확인한 사용자가 있을 때, **When** 다음 버튼을 누르면, **Then** 카메라 권한 안내 화면(`/onboarding`)으로 이동해야 한다.

---

### User Story 2 - 카메라 권한 안내를 확인하고 진행한다 (Priority: P1)

온보딩 소개를 마친 사용자는 카메라 사용 안내 화면에서 웹캠이 자세 분석에만 사용되고 데이터는 PC에만 저장된다는 점을 확인한 뒤, 보정 화면으로 진입할 수 있어야 한다.

**Why this priority**: 카메라 권한 안내는 보정 측정의 전제 조건이며, 사용자 프라이버시 안내도 포함하고 있어 보정 흐름과 함께 P1으로 이관해야 한다.

**Independent Test**: `/onboarding` 페이지에서 카메라 사용 안내 문구, 프라이버시 안내, 진행 버튼이 레거시와 동일하게 표시되는지 확인하면 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 `/onboarding`에 진입했을 때, **When** 카메라 권한 안내 화면이 렌더링되면, **Then** 웹캠 사용 목적 안내와 "데이터는 PC에만 저장된다"는 프라이버시 안내 문구가 레거시와 동일하게 표시되어야 한다.
2. **Given** 카메라 권한 안내 화면이 표시될 때, **When** 사용자가 진행 버튼을 누르면, **Then** 보정 화면(`/onboarding/calibration`)으로 이동해야 한다.

---

### User Story 3 - 보정 측정을 진행하고 결과를 확인한다 (Priority: P1)

사용자는 보정 화면에서 바른 자세 안내를 확인하고, 측정을 시작해 5초간 자세 데이터를 수집한 뒤, 측정 결과(품질 등급)를 확인할 수 있어야 한다. 측정에 실패하면 재시도할 수 있어야 한다.

**Why this priority**: 보정은 앱의 핵심 기능인 자세 분석의 기준점을 설정하는 과정이다. 보정 없이는 자세 측정이 불가능하므로 이관 최우선 항목이다.

**Independent Test**: `/onboarding/calibration`에서 웰컴 패널, 측정 진행 패널, 카메라 뷰가 레거시와 동일한 UI로 표시되는지, 측정 시작/진행/완료 흐름이 동일하게 동작하는지 확인하면 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 `/onboarding/calibration`에 진입했을 때, **When** 보정 화면이 렌더링되면, **Then** 바른 자세 안내(웰컴 패널)와 측정 시작 버튼이 레거시와 동일하게 표시되어야 한다.
2. **Given** 사용자가 바른 자세를 취하고 측정을 시작했을 때, **When** 5초간 측정이 진행되면, **Then** 카운트다운과 측정 진행 상태가 레거시와 동일하게 표시되어야 한다.
3. **Given** 5초간 측정이 완료되었을 때, **When** 측정 결과가 처리되면, **Then** 품질 등급(poor/medium/good)과 함께 완료 화면으로 이동하거나 재시도 옵션이 제공되어야 한다.
4. **Given** 측정이 실패했을 때(품질 불량, 프레임 부족 등), **When** 실패 결과가 표시되면, **Then** 사용자는 재시도 버튼을 통해 다시 측정할 수 있어야 한다.

### User Story 4 - 보정 완료 후 메인으로 진입한다 (Priority: P1)

보정을 완료한 사용자는 완료 화면에서 세션이 생성되었음을 확인하고, 메인 대시보드로 바로 진입할 수 있어야 한다.

**Why this priority**: 보정 완료는 온보딩 흐름의 끝점이며, 이후 메인 대시보드로의 전환이 원활해야 전체 사용자 경험이 이어진다.

**Independent Test**: `/onboarding/completion`에서 완료 안내와 메인 이동 버튼이 표시되는지, 버튼 클릭 시 `/main`으로 이동하는지 확인하면 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 보정 측정이 성공적으로 완료되었을 때, **When** 완료 화면이 표시되면, **Then** 보정 완료 안내 문구와 메인 화면 이동 버튼이 레거시와 동일하게 표시되어야 한다.
2. **Given** 완료 화면이 표시될 때, **When** 사용자가 메인 이동 버튼을 누르면, **Then** `/main`으로 이동하여 대시보드를 확인할 수 있어야 한다.

---

### User Story 5 - 보정 상태에 따라 올바른 경로로 이동한다 (Priority: P2)

사용자는 현재 보정 상태(초기 필요, 재보정 요청, 완료)에 따라 로그인 직후 알맞은 화면으로 자동 이동한다. 이미 보정을 마친 사용자는 온보딩을 거치지 않고 메인으로 바로 진입한다.

**Why this priority**: 보정 상태 판별은 온보딩 흐름과 메인 페이지 진입을 올바르게 연결하는 핵심 로직이다. 흐름이 틀어지면 사용자가 불필요한 화면을 반복하거나 보정 없이 메인에 진입하게 된다.

**Independent Test**: 보정 상태별(localStorage 값)로 로그인 후 이동 경로가 올바른지 확인하면 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 보정을 한 번도 하지 않은 사용자가 로그인했을 때, **When** 인증이 완료되면, **Then** `/onboarding/init`으로 이동해야 한다.
2. **Given** 보정을 이미 완료한 사용자가 로그인했을 때, **When** 인증이 완료되면, **Then** `/main`으로 바로 이동해야 한다.
3. **Given** 보정 초기화를 요청한 사용자가 로그인했을 때, **When** 인증이 완료되면, **Then** `/onboarding/calibration`으로 이동해야 한다.
4. **Given** 보정 흐름 진입 중인 사용자가 보정이 필요 없는 상태가 되었을 때, **When** 보정 관련 라우트에 접근하면, **Then** `/main`으로 리다이렉트되어야 한다.

### Edge Cases

- 카메라 접근 권한이 거부된 상태에서 보정 화면에 진입하더라도 화면이 깨지지 않고 권한 요청 안내가 표시되어야 한다.
- 보정 데이터(localStorage)가 손상되거나 예상치 못한 값인 경우 초기 보정이 필요한 상태로 처리되어야 한다.
- 측정 중 브라우저 탭이 포커스를 잃거나 화면이 최소화되더라도 측정 상태가 무한정 대기하지 않아야 한다. (Tauri 데스크톱 앱에서도 윈도우 최소화 시 동일하게 적용되며, 구체적인 타임아웃 처리는 008에서 다룬다)
- 보정 재시도 시 이전 측정 데이터는 완전히 초기화되고 새로 측정이 시작되어야 한다.
- 네트워크가 불안정하여 세션 생성 요청이 실패하더라도 보정 완료 화면은 정상적으로 표시되어야 한다.
- 자세 측정 파이프라인(MediaPipe 연동, 실시간 PI 계산)은 이번 스펙 범위에서 제외하고, 후속 스펙(008)에서 다룬다. 이번에는 보정 UI 흐름과 상태 관리까지만 이관한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 처음 로그인하거나 보정이 필요한 사용자를 `/onboarding/init`으로 자동 이동시켜야 한다.
- **FR-002**: 시스템은 `/onboarding/init`에서 앱 핵심 기능(자세 분석, 실시간 위젯, 대시보드, 알림, 게임)을 5단계 슬라이드로 안내해야 하며, 각 단계의 이미지와 설명, 진행 표시자가 레거시와 동일해야 한다.
- **FR-003**: 시스템은 5단계 소개 완료 후 카메라 사용 안내 화면(`/onboarding`)으로 이동해야 하며, 웹캠 사용 목적과 프라이버시 안내가 레거시와 동일하게 표시되어야 한다.
- **FR-004**: 시스템은 카메라 안내 화면에서 진행 시 보정 화면(`/onboarding/calibration`)으로 이동해야 한다.
- **FR-005**: 시스템은 보정 화면에서 바른 자세 안내(웰컴 패널), 측정 진행 상태(측정 패널), 카메라 뷰를 레거시와 동일한 레이아웃으로 제공해야 한다.
- **FR-006**: 시스템은 보정 측정 시 5초간 카운트다운을 표시하고 측정 진행 상태를 실시간으로 보여줘야 한다.
- **FR-007**: 시스템은 측정 완료 후 품질 등급(poor/medium/good)을 판정하여 저장하고, 성공 시 완료 화면으로 이동해야 한다. (이번 스펙(007)에서는 측정 엔진 미연결로 인해 구현하지 않으며, 후속 스펙(008)에서 다룬다)
- **FR-008**: 시스템은 측정 실패 시 재시도 옵션을 제공해야 하며, 이전 측정 데이터를 초기화하고 다시 측정할 수 있어야 한다. (이번 스펙(007)에서는 측정 엔진 미연결로 인해 구현하지 않으며, 후속 스펙(008)에서 다룬다)
- **FR-009**: 시스템은 보정 완료 후 완료 화면(`/onboarding/completion`)에서 세션 생성 요청을 보내고 메인 이동 버튼을 제공해야 한다.
- **FR-010**: 시스템은 보정 게이트(CalibrationGate)를 통해 사용자의 보정 상태(초기 필요, 재보정 요청, 완료)를 판별하고, 상태에 따라 로그인 후 이동 경로를 결정해야 한다.
- **FR-011**: 시스템은 보정 상태를 사용자별로 localStorage에 저장하고 관리해야 한다.
- **FR-012**: 시스템은 이미 보정을 마친 사용자가 보정 관련 라우트에 접근하면 `/main`으로 리다이렉트해야 한다.
- **FR-013**: 시스템은 보정 완료 후 보정 게이트 상태를 `locked`로 변경하고 보정 결과를 localStorage에 저장해야 한다.
- **FR-014**: 시스템은 온보딩/보정 화면의 모든 문자열을 i18n 리소스로 분리하여 다국어 처리 기반을 유지해야 한다.
- **FR-015**: 시스템은 온보딩/보정 화면의 UI 스타일을 레거시와 동일하게 유지해야 한다.
- **FR-016**: 시스템은 자세 측정 파이프라인(MediaPipe, PI 계산, 실시간 분석)의 실제 구현은 이번 범위에서 제외하고, UI 흐름과 상태 관리 이관에 집중해야 한다. 이번에는 보정 UI에서 측정 엔진이 연결될 진입점만 마련한다. (FR-007, FR-008, FR-013도 이 제약의 대상이다)
- **FR-017**: 시스템은 보정 측정 엔진이 아직 연결되지 않은 상태에서는 보정 화면에 미연결 안내 메시지를 표시하고 측정 시작 버튼을 비활성화해야 한다. 후속 스펙(008)에서 측정 엔진이 연결되면 해당 안내 메시지가 사라지고 정상 측정 흐름이 활성화된다. (FR-016의 구체화)

### Key Entities

- **보정 게이트 상태(CalibrationGate)**: 사용자의 보정 필요 여부를 판별하는 상태 값이다. `initial_required`(초기 보정 필요), `reset_requested`(재보정 요청), `locked`(보정 완료) 세 가지 값을 가진다. 사용자 ID별로 localStorage에 저장된다.
- **보정 결과(CalibrationResult)**: 보정 측정 완료 후 저장되는 결과 데이터다. 평균 PI값, 표준편차, 통과율, 품질 등급, 통과 프레임 수, 전체 프레임 수, 타임스탬프를 포함한다.
- **보정 프레임(CalibrationFrame)**: 보정 측정 중 수집되는 단일 프레임 데이터다. 포즈 랜드마크, PI 계산 결과, 3D 랜드마크, EMA 평활값, 프레임 밝기를 포함한다.
- **온보딩 진행 상태(OnboardingProgress)**: 사용자가 온보딩 흐름의 어느 단계에 있는지를 나타낸다. 소개 단계, 카메라 권한, 보정 측정, 완료의 단계로 구성된다.
- **측정 품질 등급(CalibrationQuality)**: 보정 결과의 품질을 나타내는 등급이다. `poor`, `medium`, `good`, `unknown` 네 가지 값을 가진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 처음 로그인한 사용자가 온보딩 소개 → 카메라 안내 → 보정 측정 → 완료의 전체 흐름을 레거시와 동일한 화면 전환으로 진행할 수 있다.
- **SC-002**: 레거시와 마이그레이션 온보딩 화면의 시각 비교에서 각 단계의 레이아웃, 텍스트, 이미지, 버튼 구성에 차이가 없어야 한다.
- **SC-003**: 보정 상태(초기/재보정/완료)에 따라 로그인 후 이동 경로가 100% 정확하게 분기된다.
- **SC-004**: 보정 측정 UI의 카운트다운, 진행 상태, 결과 표시가 레거시와 동일한 흐름으로 동작한다.
- **SC-005**: 보정 완료 후 메인 대시보드로의 전환이 네비게이션 즉시 실행되어 체감 지연이 없어야 한다.

## Assumptions

- 이번 스펙은 레거시 `src/renderer/src/pages/`의 온보딩 관련 4개 페이지(onboarding-init, onboarding, calibration, onboarding-completion)와 관련 컴포넌트를 기준으로 한다.
- 마이그레이션 앱에 이미 온보딩 라우트(`/onboarding/*`)와 최소 페이지 구조가 존재하므로, 이를 확장하는 방식으로 진행한다.
- 자세 측정 파이프라인(MediaPipe 연동, 실시간 PI 계산, 포즈 분류)은 이번 범위에서 제외하며, 후속 스펙(008)에서 다룬다.
- 보정 측정 엔진이 연결되기 전까지 보정 화면은 UI 레이아웃(웰컴 패널, 측정 패널, 카메라 뷰)을 레거시와 동일하게 렌더링하되, 측정 엔진 미연결 안내 메시지를 표시하고 측정 시작 버튼을 비활성화 상태로 둔다.
- 보정 데이터는 클라이언트 localStorage에만 저장되며, 서버 동기화는 이번 범위에 포함하지 않는다.
- 인증 도메인(003)의 구현 결과를 그대로 재사용하며, 인증 완료 후 보정 게이트 판별 로직을 연결한다.
- 메인 대시보드(006)의 라우트와 레이아웃이 이미 구현되어 있어, 보정 완료 후 메인 진입이 가능하다.
- 세션 생성 API는 기존 `POST /sessions` 엔드포인트를 사용한다.
- 온보딩 소개의 5단계 이미지는 레거시 에셋을 그대로 사용한다.
