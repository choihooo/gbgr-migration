# UI Contract: AverageGraphPanel

## 목적

`AverageGraphPanel`이 migration 앱에서 반드시 만족해야 하는 레거시 동등 UI 계약을 정의한다.

## 1. 렌더링 계약

- 패널은 카드 내부에서 세로 방향으로 배치되어야 한다.
- 상단 행에는 좌측 `바른 자세 점수` 헤더와 우측 주간/월간 토글이 있어야 한다.
- 헤더 오른쪽 정보 아이콘은 기존 migration `PanelHeader` 동작을 그대로 따른다.
- 헤더 아래 우측 정렬 범례는 노란 점과 `점수` 텍스트를 포함해야 한다.
- 메인 영역은 면적 그래프 1개를 렌더링해야 한다.

## 2. 데이터 계약

- 입력 데이터 원본은 `usePostureGraphQuery()`가 반환하는 `data.points`를 기준으로 한다.
- 입력 데이터가 존재하면 키를 정렬한 뒤 기간 규칙에 따라 잘라서 사용해야 한다.
- 입력 데이터가 비어 있으면 대체 데이터를 생성해 레이아웃을 유지해야 한다.
- 개별 점수가 `0`이면 레거시와 같은 대체 점수 규칙을 적용할 수 있다.

## 3. 상호작용 계약

- 토글이 `false`일 때는 `weekly`, `true`일 때는 `monthly` 상태여야 한다.
- `weekly` 상태에서는 최근 7개 데이터만 보여야 한다.
- `monthly` 상태에서는 전체 데이터를 보여야 한다.
- `monthly` 상태에서 데이터 개수가 12개를 초과하면 차트는 가로 스크롤 가능해야 한다.

## 4. 시각 계약

- 차트는 `AreaChart` 기반이어야 하며, 실선 1개와 면적 채움 1개를 표시해야 한다.
- y축 최대값은 100이어야 한다.
- y축 눈금은 `25`, `50`, `75`, `100`을 유지해야 한다.
- x축 라벨은 순번 문자열을 사용해야 한다.
- 그리드는 가로선만 표시해야 한다.
- 툴팁은 상단 근처에 표시되고, 배경/테두리/패딩 규칙은 레거시와 동일해야 한다.

## 5. 회귀 방지 계약

- 패널 외곽 카드 반경, 배경색, 주변 레이아웃은 `LeftPanelArea`의 기존 스타일을 유지해야 한다.
- `AverageGraphPanel` 이관으로 `HighlightsPanel`, `PosePatternPanel`, `TotalDistancePanel`의 크기 계산이 바뀌면 안 된다.
- 레거시 동등성 검증 시 제목, 범례, 축, 그리드, 면적 채움, 월간 스크롤 여부를 우선 비교해야 한다.
