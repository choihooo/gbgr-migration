# Feature Specification: AverageGraphPannel UI 이관

**Feature Branch**: `[014-average-graph-panel]`  
**Created**: 2026-04-15  
**Status**: Draft  
**Input**: User description: "AverageGraphPannel 이거 레거시에서 migration으로 ui 똑같이 이관해줘"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 동일한 그래프 확인 (Priority: P1)

대시보드 사용자는 migration 앱에서도 레거시 앱과 동일한 바른 자세 점수 그래프 패널을 보고 싶다. 그래프의 제목, 토글, 범례, 축, 면적 그래프, 스크롤 동작이 레거시와 같아야 화면 전환 후에도 이질감 없이 사용할 수 있다.

**Why this priority**: 메인 대시보드 핵심 패널 중 하나이며, 시각적 차이가 발생하면 마이그레이션 품질이 바로 드러난다.

**Independent Test**: migration 대시보드에서 `AverageGraphPanel`만 렌더링해 레거시 화면과 비교했을 때 패널 구조와 주요 시각 요소가 동일하면 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 migration 대시보드 좌측 영역을 보고 있을 때, **When** 바른 자세 점수 패널이 렌더링되면, **Then** 패널 헤더, 주간/월간 토글, 우측 범례, 면적 그래프가 레거시와 동일한 배치로 표시된다.
2. **Given** 그래프 데이터가 존재할 때, **When** 패널이 데이터를 표시하면, **Then** x축, y축, 그리드, 툴팁, 면적 채움과 선 색상이 레거시와 동일한 방식으로 표시된다.

---

### User Story 2 - 기간 전환 유지 (Priority: P2)

대시보드 사용자는 주간과 월간 보기를 전환했을 때 레거시와 같은 상호작용을 기대한다. 기간에 따라 표시 데이터 범위와 가로 스크롤 여부가 동일하게 바뀌어야 한다.

**Why this priority**: 패널의 핵심 상호작용이며, 기간 전환 시 UI가 다르면 레거시 동일성 요구를 충족하지 못한다.

**Independent Test**: 토글을 주간과 월간으로 각각 전환해 데이터 개수, 축 라벨, 가로 스크롤 표시 여부가 레거시와 같은지 확인하면 된다.

**Acceptance Scenarios**:

1. **Given** 사용자가 주간 보기를 보고 있을 때, **When** 월간 토글로 전환하면, **Then** 월간 데이터가 표시되고 항목 수가 많을 경우 레거시와 동일하게 가로 스크롤이 가능해야 한다.
2. **Given** 사용자가 월간 보기를 보고 있을 때, **When** 다시 주간 토글로 전환하면, **Then** 최근 주간 범위만 표시되고 가로 스크롤은 사라져야 한다.

---

### User Story 3 - 데이터 부재 시 일관된 표시 (Priority: P3)

대시보드 사용자는 서버 데이터가 비어 있거나 일부 값이 비정상이어도 패널이 깨지지 않고 그래프 형태를 유지하길 원한다.

**Why this priority**: 마이그레이션 초기에 API 응답 편차가 있어도 패널이 비정상적으로 보이지 않게 해야 한다.

**Independent Test**: 그래프 응답이 비어 있거나 일부 점수가 0인 상태로 패널을 렌더링해도 레거시와 같은 대체 표시가 유지되는지 확인하면 된다.

**Acceptance Scenarios**:

1. **Given** 그래프 응답이 비어 있을 때, **When** 패널이 렌더링되면, **Then** 레거시와 같은 형식의 대체 데이터로 그래프 레이아웃이 유지되어야 한다.
2. **Given** 그래프 점수 일부가 0일 때, **When** 해당 데이터를 그래프에 반영하면, **Then** 레거시와 같은 방식으로 시각적 공백 없이 그래프가 유지되어야 한다.

### Edge Cases

- 월간 데이터가 12개를 초과할 때도 각 항목 폭이 지나치게 압축되지 않고 레거시처럼 가로 스크롤로 나머지 데이터를 볼 수 있어야 한다.
- 서버 응답의 날짜 키가 정렬되지 않아도 레거시와 같은 순서 규칙으로 표시되어야 한다.
- 그래프 점수에 0이 포함되거나 전체 데이터가 비어 있어도 패널 높이와 축 구조가 깨지지 않아야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 migration 대시보드에서 `AverageGraphPannel`의 시각적 구조를 레거시와 동일하게 표시해야 한다.
- **FR-002**: 시스템은 패널 상단에 레거시와 동일한 제목, 정보 아이콘, 주간/월간 토글을 표시해야 한다.
- **FR-003**: 시스템은 패널 우측 상단 범례를 레거시와 동일한 위치와 텍스트로 표시해야 한다.
- **FR-004**: 시스템은 그래프를 면적 그래프 형태로 표시하고, 축, 그리드, 툴팁, 채움 색상, 선 색상을 레거시와 동일한 규칙으로 표현해야 한다.
- **FR-005**: 시스템은 주간 보기에서 최근 7개 구간만 표시하고, 월간 보기에서는 전체 구간을 표시해야 한다.
- **FR-006**: 시스템은 월간 구간 수가 12개를 초과하면 레거시와 동일하게 가로 스크롤을 제공해야 한다.
- **FR-007**: 시스템은 그래프 응답이 비어 있을 때도 레거시와 동일한 형식의 대체 데이터로 패널 레이아웃을 유지해야 한다.
- **FR-008**: 시스템은 일부 점수 값이 0인 경우에도 레거시와 동일한 방식으로 그래프를 끊김 없이 표시해야 한다.
- **FR-009**: 시스템은 기존 migration 대시보드 레이아웃과 패널 크기 제약 안에서 레거시 스타일을 유지해야 한다.

### Key Entities *(include if feature involves data)*

- **자세 그래프 포인트 집합**: 기간별 라벨과 점수로 구성된 시계열 데이터 모음이며, 패널의 x축 라벨과 그래프 선을 구성한다.
- **그래프 표시 기간**: 사용자가 선택한 주간 또는 월간 상태이며, 표시할 데이터 범위와 스크롤 동작을 결정한다.
- **차트 표시 설정**: 축 범위, 눈금, 색상, 채움, 그리드 같은 시각 규칙 묶음이며, 레거시 동일성을 보장한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: migration의 `AverageGraphPanel`은 레거시 `AverageGraphPannel`과 비교했을 때 제목, 토글, 범례, 그래프, 축, 스크롤 구조가 모두 일치해야 한다.
- **SC-002**: 사용자는 주간과 월간 전환 후 1초 이내에 올바른 기간 데이터와 축 라벨 변화를 확인할 수 있어야 한다.
- **SC-003**: 그래프 데이터가 비어 있거나 일부 값이 0이어도 패널 레이아웃 깨짐 없이 100% 렌더링되어야 한다.
- **SC-004**: 검증 과정에서 패널 이관으로 인해 다른 좌측 대시보드 패널의 배치나 스타일 회귀가 발생하지 않아야 한다.

## Assumptions

- 기존 대시보드 자세 그래프 응답 형식은 migration에서도 그대로 재사용할 수 있다고 가정한다.
- 레거시와 동일한 UI를 위해 기존 migration의 임시 SVG 그래프 구현은 교체 가능하다고 가정한다.
- 패널 외곽 카드 스타일과 좌측 영역 레이아웃은 이미 migration에서 맞춰져 있으므로 이번 작업에서는 패널 내부 UI 동일성에 집중한다고 가정한다.
- 레거시와 동일한 랜덤 대체 데이터 규칙은 실제 API가 안정화되기 전까지 유지한다고 가정한다.
