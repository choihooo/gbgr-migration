# Research: AverageGraphPannel UI 이관

## 결정 1: 차트 렌더링 방식은 `recharts` `AreaChart`를 사용한다

- 결정: migration의 `AverageGraphPanel`은 레거시와 동일하게 `ResponsiveContainer`, `AreaChart`, `CartesianGrid`, `XAxis`, `YAxis`, `Tooltip`, `Area` 조합으로 렌더링한다.
- 근거: 레거시 구현이 이미 같은 구조를 사용하고 있고, migration에도 `HighlightsPanel`에서 `recharts`가 사용 중이라 의존성과 스타일 계산 패턴을 재사용할 수 있다.
- 고려한 대안:
  - 기존 임시 SVG 유지: 레거시와 축, 툴팁, 그리드, 스크롤 동작이 달라 동일성 요구를 만족하지 못해 제외
  - 다른 차트 라이브러리 도입: 기존 의존성과 패턴을 벗어나며 단일 패널 이관 범위를 불필요하게 키워 제외

## 결정 2: 기간 전환 규칙은 레거시의 데이터 슬라이싱 규칙을 그대로 따른다

- 결정: 주간은 정렬된 최근 7개 구간만 표시하고, 월간은 전체 구간을 표시한다.
- 근거: 레거시 `useAverageGraphChart`가 이 규칙을 사용하며, 사용자 기대도 레거시 동작과의 일치에 맞춰져 있다.
- 고려한 대안:
  - API에서 전달된 원래 라벨을 그대로 노출: 현재 레거시는 순번 라벨을 사용하므로 시각 차이가 생겨 제외
  - 월간도 고정 4주만 표시: 레거시가 전체 구간을 허용하므로 제외

## 결정 3: 월간 데이터가 12개를 초과하면 가로 스크롤을 제공한다

- 결정: 월간 상태에서 데이터가 12개를 넘을 때만 차트 컨테이너에 수평 스크롤을 활성화하고, 차트 폭을 데이터 개수에 비례해 확장한다.
- 근거: 레거시 구현이 같은 조건으로 차트 너비를 계산해 항목 압축을 방지한다.
- 고려한 대안:
  - 모든 기간에서 스크롤 허용: 주간에서는 불필요하고 레거시와 다르므로 제외
  - 차트 폭 고정 후 눈금만 압축: 레거시와 다른 시각적 밀도를 만들어 제외

## 결정 4: 데이터 공백과 `0` 점수는 레거시의 임시 대체 규칙을 유지한다

- 결정: 응답이 비어 있으면 주간 7개 또는 월간 31개의 임시 점수를 생성하고, 개별 점수가 `0`이면 레거시와 같은 범위의 대체 점수로 치환한다.
- 근거: migration 초기에는 API 편차 가능성이 있고, 레거시도 같은 보호 로직을 사용해 패널 붕괴를 방지한다.
- 고려한 대안:
  - 빈 그래프 그대로 노출: 사용자가 패널 고장으로 인식할 수 있어 제외
  - `0` 값을 실제 0점으로 렌더링: 레거시와 시각적으로 달라지고 선이 바닥으로 급락해 제외

## 결정 5: 공용 UI와 색상 계산은 migration의 기존 유틸을 사용한다

- 결정: 헤더는 `PanelHeader`, 토글은 `ToggleSwitch`, 차트 색상은 `useThemeApplied`와 `getColor`를 사용한다.
- 근거: migration 쪽에서 이미 같은 역할의 공용 컴포넌트와 유틸이 존재하고, `HighlightsPanel`도 동일 패턴을 사용한다.
- 고려한 대안:
  - 패널 내부에 별도 헤더/토글/색상 계산 구현: 중복이 생기고 이후 패널 이관과의 일관성이 떨어져 제외

## 결정 6: 검증 방식은 정적 검사와 레거시 수동 비교를 조합한다

- 결정: `bun x tsc --noEmit`, `bun x biome check`로 코드 정합성을 확인하고, 최종 UI는 레거시 캡처 또는 실행 화면과 수동 비교한다.
- 근거: 이번 변경은 조회형 정적 UI 중심이라 자동 테스트보다 시각 비교가 회귀 탐지에 더 직접적이다.
- 고려한 대안:
  - 별도 테스트 강제 작성: 리스크 대비 비용이 높고 헌법의 테스트 원칙과도 맞지 않아 제외
