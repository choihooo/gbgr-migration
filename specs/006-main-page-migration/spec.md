## User Scenarios & Testing *(mandatory)*

### User Story 1 - 대시보드 메인 화면을 동일하게 본다 (Priority: P1)

인증을 마친 사용자는 `migration` 앱의 `/main`에 진입했을 때 레거시 메인 페이지와 동일한 헤더, 좌우 컬럼 레이아웃, 스크롤 구조, 카드 배치를 확인할 수 있어야 한다.

**Why this priority**: 메인 페이지는 로그인 이후 사용자가 가장 먼저 마주치는 핵심 화면이며, 대시보드 뼈대가 이관되어야 이후 패널별 기능과 데이터 연결을 안정적으로 진행할 수 있다.

**Independent Test**: 로그인된 상태에서 `/main`에 진입해 좌측 대시보드 패널 영역과 우측 웹캠/러닝 영역이 레거시와 동일한 위치와 순서로 렌더링되는지 확인하면 이 스토리를 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 인증된 상태로 `/main`에 진입했을 때, **When** 메인 페이지가 렌더링되면, **Then** 레거시와 동일한 메인 전용 헤더와 2열 레이아웃이 표시되어야 한다.
2. **Given** 좌측 대시보드 영역의 콘텐츠 높이가 화면 높이를 초과할 때, **When** 사용자가 내용을 확인하면, **Then** 레거시와 동일하게 좌측 패널 영역만 내부 스크롤되어야 한다.
3. **Given** 우측 웹캠/러닝 영역의 콘텐츠가 길어질 때, **When** 사용자가 내용을 확인하면, **Then** 우측 패널 영역만 독립적으로 스크롤되어야 한다.

---

### User Story 2 - 주요 대시보드 패널을 한 화면에서 확인한다 (Priority: P1)

인증된 사용자는 평균 자세 점수, 출석 현황, 이동거리, 그래프, 하이라이트, 자세 패턴, 웹캠, 러닝 요약 등 레거시 메인 페이지의 주요 패널을 같은 구성으로 확인할 수 있어야 한다.

**Why this priority**: 사용자가 메인 페이지에서 기대하는 핵심 가치는 여러 요약 정보를 한눈에 보는 것이다. 패널 구성이 빠지면 메인 페이지 이관의 의미가 크게 줄어든다.

**Independent Test**: `/main` 진입 후 각 패널의 존재 여부, 배치 순서, 카드 컨테이너 스타일이 레거시와 동일한지 비교하면 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 메인 페이지가 정상적으로 표시될 때, **When** 사용자가 좌측 상단 영역을 보면, **Then** 평균 자세 점수 패널과 출석 현황 패널이 레거시와 동일한 위치에 보여야 한다.
2. **Given** 사용자가 좌측 하단 영역을 보면, **When** 이동거리, 그래프, 하이라이트, 자세 패턴 영역을 확인하면, **Then** 각 패널이 레거시와 동일한 그룹 구조와 카드 외형으로 표시되어야 한다.
3. **Given** 사용자가 우측 영역을 보면, **When** 웹캠 패널과 러닝 요약 패널을 확인하면, **Then** 두 패널이 동일한 순서와 구분선 구조로 표시되어야 한다.

---

### User Story 3 - 메인 페이지의 상호작용을 이어서 사용한다 (Priority: P2)

인증된 사용자는 메인 페이지에서 알림 모달 열기, 웹캠 표시 상태 변경, 메트릭 전송 트리거, 보호 화면 유지 등 기존 메인 화면의 상호작용을 이어서 사용할 수 있어야 한다.

**Why this priority**: 레이아웃만 같고 상호작용이 빠지면 메인 페이지가 정적인 복제에 머문다. 메인 화면의 기본 액션을 복원해야 이후 자세 분석 및 세션 기능을 자연스럽게 연결할 수 있다.

**Independent Test**: 메인 헤더의 알림 버튼과 웹캠 패널의 기본 액션을 실행해 알림 모달 열림과 웹캠 상태 변화가 동작하는지 확인하면 이 스토리를 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 메인 페이지를 보고 있을 때, **When** 메인 헤더의 알림 버튼을 누르면, **Then** 레거시와 동일한 알림 설정 모달이 열려야 한다.
2. **Given** 사용자가 우측 웹캠 패널을 보고 있을 때, **When** 웹캠 표시 토글을 실행하면, **Then** 웹캠 패널의 표시 상태가 레거시 흐름과 일치하게 바뀌어야 한다.
3. **Given** 메인 페이지가 보호 화면일 때, **When** 인증되지 않은 상태가 되면, **Then** 보호 콘텐츠가 유지되지 않고 인증 흐름으로 복귀해야 한다.

### Edge Cases

- 캘리브레이션 데이터가 없거나 손상된 상태에서 메인 페이지에 진입하더라도 화면 레이아웃 자체는 깨지지 않아야 한다.
- 특정 패널의 데이터가 비어 있거나 지연되더라도 다른 패널 배치와 카드 크기는 무너지지 않아야 한다.
- 웹캠 접근 권한이 없거나 웹캠 초기화가 실패해도 우측 영역 전체가 사라지지 않고 대체 상태를 보여야 한다.
- 알림 모달이 열려 있는 동안에도 메인 페이지 배경 레이아웃은 레거시와 같은 상태를 유지해야 한다.
- 이번 이관 범위에서는 웹 MediaPipe를 Python 자세 분석 엔진으로 전환하지 않으며, 기존 자세 분석 흐름은 별도 기능으로 분리되어야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 인증된 사용자가 `/main`에 진입했을 때 레거시 메인 페이지와 동일한 메인 전용 헤더와 2열 레이아웃을 표시해야 한다.
- **FR-002**: 시스템은 좌측 대시보드 영역과 우측 웹캠/러닝 영역을 서로 독립적인 스크롤 구조로 제공해야 한다.
- **FR-003**: 시스템은 평균 자세 점수, 출석 현황, 이동거리, 그래프, 하이라이트, 자세 패턴, 웹캠, 러닝 요약 패널을 레거시와 동일한 순서와 그룹 구조로 제공해야 한다.
- **FR-004**: 시스템은 각 패널 컨테이너의 카드 외형, 간격, 둥근 모서리, 배경색, 구분선 등 시각 스타일을 레거시와 동일하게 유지해야 한다.
- **FR-005**: 시스템은 메인 페이지의 알림 버튼을 통해 알림 설정 모달을 열고 닫을 수 있어야 한다.
- **FR-006**: 시스템은 메인 페이지의 웹캠 표시 관련 기본 상호작용(show/hide/exit 상태 전환)을 유지해야 한다. 단, 위젯 창 제어는 후속 단계로 분리한다.
- **FR-007**: 시스템은 메인 페이지가 보호 화면으로서 인증 상태 변화에 따라 접근이 제어되어야 하며, 미인증 상태에서 보호 콘텐츠를 계속 노출해서는 안 된다.
- **FR-008**: 시스템은 메인 페이지 이관 과정에서 페이지 조립 책임과 패널별 상태/행동 책임을 분리해야 하며, 페이지 컴포넌트는 데이터 페칭·비즈니스 로직을 직접 포함하지 않고 화면 조합만 담당해야 한다.
- **FR-009**: 시스템은 레거시 메인 페이지에서 사용하던 마지막 갱신 문구, 패널 구분, 내부 스크롤 패턴을 사용자 관점에서 동일하게 제공해야 한다. 마지막 갱신 문구는 레거시 표시값("마지막 갱신일: 2025.10.22(수) 17:52")을 그대로 표시하며, 실시간 값으로 대체하지 않는다.
- **FR-010**: 시스템은 메인 페이지 이관 범위에서 기존 웹 기반 자세 분석 흐름을 유지하되, Python 기반 자세 분석 엔진 전환은 별도 기능으로 다뤄야 한다.
- **FR-011**: 시스템은 메인 페이지 이관 결과를 레거시 화면과 비교할 수 있도록 before/after 스크린샷 형태의 시각 검증 산출물을 남겨야 한다.
- **FR-012**: 시스템은 이번 이관 범위에서 메인 페이지의 레이아웃, 패널 UI, 기본 상호작용을 우선 제공해야 하며, 복잡한 데이터 연동(그래프 계산, 실시간 집계, 분석 로직)과 자세 분석 엔진 연동은 후속 단계로 분리해야 한다.
- **FR-013**: 시스템은 각 패널의 내부를 제목과 빈 카드 수준으로 축약하지 않고, 레거시에서 사용자가 현재 확인할 수 있는 기본 UI 구조와 기본 상태를 동일하게 제공해야 한다.
- **FR-016**: 시스템은 메인 페이지에서 사용자가 볼 수 있는 위젯 관련 진입점, 세션 관련 기본 트리거, 메트릭 전송 시작 지점을 유지해야 한다.
- **FR-017**: 시스템은 위젯 창 제어, 세션 종료 완료, 메트릭 전송 완료 보장처럼 화면 밖 시스템 동작의 완전한 이관은 이번 범위에서 제외하고 후속 단계로 분리해야 한다.

### Key Entities *(include if feature involves data)*

- **메인 페이지 레이아웃**: 메인 전용 헤더, 좌측 대시보드 영역, 우측 웹캠/러닝 영역, 내부 스크롤 컨테이너로 구성되는 화면 구조다.
- **대시보드 패널 집합**: 평균 자세 점수, 출석 현황, 이동거리, 그래프, 하이라이트, 자세 패턴, 웹캠, 러닝 요약처럼 메인 페이지를 구성하는 카드 단위 묶음이다.
- **패널 기본 상태**: 각 패널이 레거시 메인 페이지에서 초기 진입 시 보여주는 제목, 요약 수치, 비어 있지 않은 기본 레이아웃, 버튼/라벨 상태를 뜻한다.
- **메인 페이지 상호작용 상태**: 알림 모달 열림 여부, 웹캠 표시 상태, 보호 화면 접근 상태처럼 메인 페이지에서 유지해야 하는 사용자 상호작용 상태다.
- **시스템 연계 트리거**: 메인 페이지에서 사용자가 실행할 수 있는 위젯 관련 진입점, 세션 정리 시작점, 메트릭 전송 시작점처럼 후속 시스템 기능과 연결되는 출발 지점이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 인증된 사용자가 `/main`에 진입했을 때 메인 전용 헤더와 핵심 패널 8종을 한 화면 내에서 모두 확인할 수 있다.
- **SC-002**: 레거시와 마이그레이션 메인 페이지의 시각 비교에서 패널 배치 순서와 그룹 구조 차이가 없어야 한다.
- **SC-003**: 좌측 대시보드 영역과 우측 웹캠/러닝 영역은 각각 독립적으로 스크롤되며, 한쪽 스크롤이 다른 쪽 레이아웃을 깨뜨리지 않아야 한다.
- **SC-004**: 사용자는 메인 페이지에서 알림 모달 열기와 웹캠 기본 상호작용을 별도 화면 이동 없이 완료할 수 있어야 한다.

## Assumptions

- 메인 페이지 이관은 현재 레거시 `src/renderer/src/pages/main-page/index.tsx`와 관련 패널 구성 요소를 기준으로 한다.
- 패널별 데이터 로직이 아직 완전히 이관되지 않은 경우에도 레이아웃과 화면 조합의 충실한 복제가 우선이다.
- 이번 스펙의 완료 기준은 레이아웃, 패널 UI, 기본 상호작용 복원까지이며, 실데이터 동기화와 분석 엔진 치환은 후속 스펙에서 다룬다.
- 패널 내부는 레거시의 초기 표시 상태를 기준으로 복원하며, 계산 결과의 실시간 정확도까지 이번 범위에서 요구하지 않는다.
- 마지막 갱신 문구는 이번 단계에서 실시간 데이터와 연결하지 않고 레거시 표시값을 그대로 유지한다.
- 위젯 창 제어, 세션 종료 완료, 메트릭 전송 완료 자체는 후속 시스템 기능 이관 범위이며, 이번 단계에서는 화면에 드러나는 트리거와 연결 지점만 유지한다.
- Python 기반 자세 분석 엔진 전환은 이번 스펙 범위에 포함하지 않으며, 추후 별도 스펙에서 다룬다.
- 알림 설정 모달은 이미 이관된 모달 컴포넌트를 재사용한다.
- 메인 페이지는 `/main` 보호 라우트에서 동작하며, 인증 도메인 구현 결과를 그대로 재사용한다.
