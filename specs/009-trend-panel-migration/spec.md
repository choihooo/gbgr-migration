# Feature Specification: TrendPanel 이관

**Feature Branch**: `009-trend-panel-migration`
**Created**: 2026-04-15
**Status**: Draft

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 트렌드 패널을 레거시와 동일하게 본다 (Priority: P1)

메인 페이지를 사용하는 사용자는 TrendPanel이 마이그레이션 앱에서도 레거시와 같은 카드 외형, 제목, 필터 버튼, 차트 영역 비율로 보여야 한다.

**Why this priority**: TrendPanel은 대시보드 분석 문서에서 CharacterPanel 다음으로 이관 가능한 Tier 1 패널로 분류되어 있다. 제목과 버튼이 포함된 카드 구조를 정확히 복제하는 것이 이후 복잡한 패널 이관의 기준선이 된다.

**Independent Test**: TrendPanel을 렌더링한 뒤 레거시 화면과 나란히 비교하여 카드 외곽선, 배경색, 제목 문구, 필터 버튼 스타일, 차트 영역이 동일한지 확인하면 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 마이그레이션 앱에서 TrendPanel이 배치된 영역을 보고 있을 때, **When** 패널이 표시되면, **Then** 레거시와 동일한 흰색 카드 컨테이너, 테두리, 둥근 모서리, 내부 여백이 보여야 한다.
2. **Given** TrendPanel이 렌더링되었을 때, **When** 사용자가 패널 상단을 보면, **Then** 레거시와 동일하게 "자세 추이" 제목과 "주간", "월간" 필터 버튼이 표시되어야 한다.
3. **Given** TrendPanel이 렌더링되었을 때, **When** 사용자가 패널 하단을 보면, **Then** 레거시와 동일한 높이의 차트 영역이 표시되어야 한다.
4. **Given** 사용자가 동일 해상도에서 레거시 화면과 마이그레이션 화면을 비교할 때, **When** TrendPanel의 위치와 크기를 확인하면, **Then** 육안 식별 가능한 시각 차이가 없어야 한다.

### User Story 2 - 다른 패널 이관의 기준으로 사용한다 (Priority: P2)

개발팀과 검증 담당자는 TrendPanel 이관 결과를 기준으로, 제목과 버튼이 포함된 카드 패널 이관이 어떤 수준인지 판단할 수 있어야 한다.

**Why this priority**: TrendPanel은 CharacterPanel보다 구조가 약간 복잡하지만(제목, 버튼, 차트 영역 포함) 여전히 무의존성이어서, 중간 복잡도 패널의 비교 기준으로 적합하다.

**Independent Test**: TrendPanel 이관 완료 후 before/after 캡처 또는 시각 비교 기록만으로 레거시 동일성 판단 기준이 문서화되어 있으면 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** TrendPanel 이관이 완료되었을 때, **When** 검증 담당자가 결과를 확인하면, **Then** 레거시 대비 동일성 여부를 판단할 수 있는 시각 비교 산출물이 있어야 한다.
2. **Given** 후속 패널 이관 작업이 시작될 때, **When** 팀이 TrendPanel 스펙을 참조하면, **Then** 제목과 버튼이 있는 카드 패널 이관 기준을 동일하게 이해할 수 있어야 한다.

### Edge Cases

- TrendPanel에 표시할 동적 데이터(차트 데이터)가 없더라도 패널 외형과 차트 영역은 항상 안정적으로 렌더링되어야 한다.
- 메인 페이지의 다른 패널이 아직 이관되지 않았거나 비어 있어도 TrendPanel 자체의 크기와 배치는 무너지지 않아야 한다.
- 창 크기가 변하더라도 반응형 컬럼 클래스(lg:col-span-6)가 레거시와 동일하게 동작해야 한다.
- 이번 이관에서는 TrendPanel의 필터 버튼에 클릭 동작, 차트 데이터 연결, 애니메이션을 추가하지 않아야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 마이그레이션 앱 내 TrendPanel을 레거시와 동일한 카드 구조(테두리, 배경, 모서리, 내부 여백)로 제공해야 한다.
- **FR-002**: 시스템은 TrendPanel 상단에 레거시와 동일한 "자세 추이" 제목을 표시해야 한다.
- **FR-003**: 시스템은 TrendPanel 상단에 레거시와 동일한 스타일의 "주간"과 "월간" 필터 버튼을 표시해야 한다.
- **FR-004**: 시스템은 TrendPanel 하단에 레거시와 동일한 높이와 배경의 차트 영역을 표시해야 한다.
- **FR-005**: 시스템은 TrendPanel 이관 과정에서 차트 데이터 연결, 버튼 클릭 동작, 애니메이션, 신규 장식 요소를 임의로 추가해서는 안 되며, UI 스타일을 변경하거나 새로운 해석을 도입해서도 안 된다.
- **FR-006**: 시스템은 TrendPanel이 다른 패널의 데이터 로딩 상태와 무관하게 독립적으로 렌더링되어야 하며, 에러 바운더리 없이 마운트 상태를 유지해야 한다.
- **FR-007**: 시스템은 TrendPanel 이관 결과에 대해 레거시 대비 시각 동일성을 확인할 수 있는 비교 산출물을 남겨야 한다.

### Key Entities *(include if feature involves data)*

- **TrendPanel 카드**: 메인 페이지 그리드 안에서 표시되는 카드 컨테이너이며, 제목 행과 차트 영역으로 구성된다.
- **필터 버튼 그룹**: "주간"과 "월간" 두 버튼으로, 서로 다른 스타일(기본/활성)로 표시된다.
- **차트 영역**: 레거시에서 차트가 렌더링되는 공간으로, 이번 이관에서는 빈 배경 영역으로만 표시한다.
- **시각 비교 산출물**: 레거시와 마이그레이션 결과를 같은 조건에서 비교해 동일성 여부를 판단할 수 있게 하는 캡처 또는 기록이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: FR-001~004가 모두 충족되는지 한 번의 화면 진입으로 확인할 수 있어야 한다.
- **SC-002**: 동일 해상도 기준 레거시와 마이그레이션 TrendPanel 비교 시 육안 식별 가능한 배치 구조 및 시각 요소 차이가 없어야 한다.
- **SC-003**: FR-005에서 금지하는 추가 요소가 이관 결과에 포함되어 있지 않아야 한다.
- **SC-004**: 팀은 TrendPanel 이관 결과를 기반으로 후속 패널 이관에서도 "레거시와 완전히 동일" 기준을 재사용할 수 있어야 한다.

## Assumptions

- TrendPanel의 기준 화면은 현재 레거시 대시보드에서 사용 중인 TrendPanel이다.
- TrendPanel은 대시보드 분석 문서에 기재된 대로 별도 데이터 연동이나 하위 구성 요소 없이 단독으로 표시되는 패널로 본다.
- 이번 스펙은 TrendPanel 단독 이관 범위에 집중하며, 메인 페이지 전체 조립이나 다른 패널 이관은 별도 스펙 범위로 유지한다.
- 레거시와 동일성 판단은 동일 해상도에서의 시각 비교를 기본 검증 방법으로 사용한다.
- "완전히 레거시와 똑같게"의 의미는 구조, 배치, 비율, 색상, 테두리, 모서리, 제목 문구, 버튼 스타일을 유지하고 임의 개선을 하지 않는 것으로 해석한다.
- 레거시 TrendPanel의 `warning-50`, `warning-600` 토큰은 현재 레거시와 마이그레이션 양쪽 모두에 정의되어 있지 않아, 이번 이관에서도 동일한 클래스명을 유지하며 토큰 정의는 후속 작업으로 남긴다.
