# Feature Specification: 자세 측정 엔진 분리 이관

**Feature Branch**: `015-posture-engine-migration`  
**Created**: 2026-04-15  
**Status**: Draft  
**Input**: User description: "docs/POSTURE_ENGINE_ARCHITECTURE.md를 기준으로 레거시 자세 측정 흐름을 Tauri 마이그레이션 앱에 맞는 별도 기능 스펙으로 정리"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 화면이 보일 때 실시간 자세 피드백 유지 (Priority: P1)

사용자는 메인 화면과 보정 화면에서 자신의 카메라 영상을 보면서 레거시와 같은 자세 피드백을 실시간으로 확인할 수 있어야 한다. 점, 선, 자세 상태, 점수 같은 피드백이 유지되어야 기존 사용 흐름이 깨지지 않는다.

**Why this priority**: 이 기능은 기존 앱의 핵심 경험이며, 사용자가 앱을 신뢰하는 가장 직접적인 근거이기 때문이다.

**Independent Test**: 메인 화면 또는 보정 화면에 진입해 카메라 미리보기와 자세 피드백이 함께 표시되는지 확인하면 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 메인 화면을 보고 있는 상태, **When** 자세 측정이 활성화되면, **Then** 카메라 영상과 자세 피드백이 동시에 표시되어야 한다.
2. **Given** 사용자가 보정 화면을 보고 있는 상태, **When** 자세 품질을 맞추기 위해 자세를 조정하면, **Then** 화면의 피드백이 즉시 갱신되어 보정 진행에 활용할 수 있어야 한다.
3. **Given** 자세 측정 엔진이 일시적으로 불안정한 상태, **When** 일부 측정 결과 수신이 실패하더라도, **Then** 메인 화면 전체가 무너지지 않고 사용자에게 마지막 정상 상태 또는 오류 상태가 유지되어야 한다.

---

### User Story 2 - 앱이 최소화되어도 측정 지속 (Priority: P2)

사용자는 앱을 최소화하거나 숨겨도 자세 측정과 알림 판단이 계속 이어지길 원한다. 화면을 보지 않는 동안에는 영상 표시가 멈춰도 되지만, 측정 세션 자체는 끊기지 않아야 한다.

**Why this priority**: 이 기능이 있어야 마이그레이션 앱이 레거시의 상시 측정 목적을 유지하면서도 창 상태 변화에 덜 흔들리는 사용자 경험을 제공할 수 있다.

**Independent Test**: 측정을 시작한 뒤 앱을 최소화하고 일정 시간 후 복귀했을 때 세션이 유지되고 최신 자세 상태가 이어지는지 확인하면 된다.

**Acceptance Scenarios**:

1. **Given** 사용자가 측정을 시작한 상태, **When** 앱 창을 최소화하거나 숨기면, **Then** 화면상의 실시간 영상은 중단되더라도 측정 세션은 계속 유지되어야 한다.
2. **Given** 앱이 최소화된 상태에서 사용자의 자세가 나빠진 경우, **When** 알림 조건이 충족되면, **Then** 사용자는 화면 복귀 여부와 무관하게 해당 세션의 판단 결과가 기록되고 알림 대상 상태가 반영되어야 한다.
3. **Given** 사용자가 다시 앱으로 복귀한 상태, **When** 메인 화면이 다시 활성화되면, **Then** 최신 자세 상태가 먼저 표시되고 이후 실시간 피드백으로 자연스럽게 이어져야 한다.

---

### User Story 3 - 안전한 모드 전환과 상태 복구 (Priority: P3)

사용자는 창 상태가 바뀌는 과정에서도 카메라 충돌, 세션 초기화, 잘못된 상태 점프 없이 자연스럽게 동작하길 원한다. 측정이 화면 표시 모드와 백그라운드 모드 사이를 오갈 때도 결과 의미가 일관되어야 한다.

**Why this priority**: 측정 자체가 유지되더라도 전환 과정에서 충돌이나 상태 손실이 생기면 신뢰성이 크게 떨어지기 때문이다.

**Independent Test**: 앱 표시 상태와 최소화 상태를 반복 전환하면서 측정 중단, 카메라 점유 충돌, 상태 초기화가 없는지 확인하면 된다.

**Acceptance Scenarios**:

1. **Given** 앱이 화면 표시 모드에서 측정 중인 상태, **When** 최소화 전환이 발생하면, **Then** 카메라 사용 권한이 한 번에 하나의 측정 주체에게만 할당되어 충돌이 발생하지 않아야 한다.
2. **Given** 앱이 백그라운드 측정 상태에 있는 상태, **When** 사용자가 앱으로 복귀하면, **Then** 이전 세션 문맥이 유지된 채 실시간 피드백이 재개되어야 한다.
3. **Given** 모드 전환 중 일시적 오류가 발생한 상태, **When** 시스템이 복구를 시도하면, **Then** 사용자에게는 엔진 상태가 명확히 드러나고 측정 가능 상태로 안전하게 복귀해야 한다.

### Edge Cases

- 사용자가 최소화와 복귀를 짧은 시간 안에 반복해도 측정 세션이 중복 생성되거나 카메라 충돌이 발생하지 않아야 한다.
- 카메라 장치를 다른 앱이 먼저 점유한 상태에서 측정을 시작하거나 전환해도 전체 화면이 깨지지 않고 측정 불가 상태가 명확히 드러나야 한다.
- 일시적으로 측정 결과가 누락되더라도 마지막 정상 결과와 세션 문맥은 유지되어야 한다.
- 사용자가 보정 화면과 메인 화면을 오가더라도 측정 의미와 피드백 기준은 동일해야 한다.
- 백그라운드 측정 중 앱이 다시 표시되었을 때 최신 결과가 없으면 오래된 값을 새 결과처럼 오인하지 않아야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사용자가 화면을 보고 있는 동안 메인 화면과 보정 화면에서 실시간 카메라 미리보기와 자세 피드백을 함께 제공해야 한다.
- **FR-002**: 시스템은 보정 화면에서 사용자가 자신의 현재 자세 품질을 보고 보정 절차를 진행할 수 있도록 최신 자세 상태를 지속적으로 반영해야 한다.
- **FR-003**: 시스템은 앱이 최소화되거나 숨김 상태가 되어도 자세 측정 세션을 계속 유지해야 한다.
- **FR-004**: 시스템은 앱이 최소화되거나 숨김 상태일 때 화면용 실시간 영상 표시를 중단해야 하며, 화면 복귀 시 다시 표시를 재개해야 한다.
- **FR-005**: 시스템은 어떤 시점에도 동일한 카메라 장치를 동시에 둘 이상의 측정 주체가 사용하지 않도록 보장해야 한다.
- **FR-006**: 시스템은 화면 표시 모드와 백그라운드 측정 모드 사이를 전환할 때 세션 식별 정보, 최신 자세 상태, 최근 측정 시각을 일관되게 유지해야 한다.
- **FR-007**: 시스템은 각 측정 결과에 대해 자세 분류, 점수, 자세 피드백 렌더링에 필요한 랜드마크 위치 정보 배열, 결과 시각을 제공해야 한다.
- **FR-008**: 시스템은 화면 복귀 직후 실시간 새 결과가 준비되기 전에도 사용자가 가장 최근 측정 상태를 확인할 수 있게 해야 한다.
- **FR-009**: 시스템은 측정 엔진 상태 변화를 사용자 인터페이스가 소비할 수 있는 형태로 제공해야 하며, 시작 중, 측정 중, 전환 중, 오류 상태를 구분할 수 있어야 한다.
- **FR-010**: 시스템은 측정 엔진 오류가 발생하더라도 메인 화면이나 보정 화면 전체가 중단되지 않도록 격리되어야 한다.
- **FR-011**: 시스템은 백그라운드 측정 중 수집된 자세 상태를 사용해 알림 판단과 세션 기록에 필요한 최신 결과를 지속적으로 제공해야 한다.
- **FR-012**: 시스템은 레거시 앱에서 사용하던 자세 판정 의미와 보정 판단 기준을 유지해야 한다.
- **FR-013**: 시스템은 기존 메인 화면과 보정 화면의 시각적 스타일을 변경하지 않은 상태에서 동작해야 한다.

### Key Entities *(include if feature involves data)*

- **측정 세션**: 한 번의 자세 측정 실행 단위이며, 시작 시각, 현재 모드, 최신 상태, 세션 지속 여부를 포함한다.
- **자세 측정 결과**: 한 시점의 자세 분류, 점수, 위치 정보, 결과 시각으로 구성된 피드백 단위이며, 화면 표시와 기록 판단의 공통 입력이 된다.
- **측정 모드**: 화면 표시 모드와 백그라운드 측정 모드로 구분되는 상태이며, 누가 카메라를 점유하고 어떤 사용자 경험을 제공하는지 결정한다.
- **카메라 점유 상태**: 현재 어떤 측정 주체가 카메라를 사용 중인지 나타내는 상태이며, 충돌 방지와 전환 순서 보장의 기준이 된다.
- **엔진 상태 이벤트**: 시작, 중지, 전환, 오류, 복구 같은 엔진 상태 변화를 표현하는 신호이며, 사용자에게 상태를 알리고 화면 동작을 조정하는 데 사용된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 메인 화면 또는 보정 화면 진입 후 2초 이내에 카메라 미리보기와 첫 자세 피드백을 확인할 수 있어야 한다.
- **SC-002**: 사용자가 앱을 최소화한 뒤 5분 이상 경과 후 복귀해도 세션이 유지되고, 복귀 후 2초 이내에 최신 상태 또는 실시간 피드백이 다시 보여야 한다.
- **SC-003**: 창 표시 상태와 최소화 상태를 10회 연속 전환해도 카메라 충돌이나 측정 세션 중복 생성이 0건이어야 한다.
- **SC-004**: 동일한 입력 자세에 대해 레거시 앱과 마이그레이션 앱의 자세 분류 결과가 검증 표본의 95% 이상에서 동일해야 한다.
- **SC-005**: 측정 엔진 오류 상황에서도 메인 화면과 보정 화면의 기본 UI는 100% 유지되고, 사용자는 현재 측정 불가 상태를 인지할 수 있어야 한다.
- **SC-006**: 레거시와 마이그레이션 화면의 비교 검수에서 메인 화면과 보정 화면의 기존 스타일 차이 항목이 0건이어야 한다.

## Assumptions

- 레거시 앱의 자세 분류 규칙, 점수 해석, 보정 판단 기준은 마이그레이션 이후에도 동일하게 유지한다고 가정한다.
- 이 기능은 단일 사용자 세션과 단일 활성 카메라 장치를 기준으로 우선 제공한다고 가정한다.
- 백그라운드 측정 중 생성되는 알림과 기록은 기존 앱이 사용하던 업무 규칙을 그대로 따른다고 가정한다.
- 카메라 접근 권한은 사용자가 이미 허용했거나, 권한 거부 시 별도의 권한 안내 흐름이 기존 범위 내에서 처리된다고 가정한다.
- 이번 스펙은 자세 측정 엔진 분리와 세션 지속성에 집중하며, 기존 `006-main-page-migration` 범위 자체를 재정의하지 않는다고 가정한다.
