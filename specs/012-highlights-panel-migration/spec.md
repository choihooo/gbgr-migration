# Feature Specification: HighlightsPanel 마이그레이션

**Created**: 2026-04-15
**Status**: Draft

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 하이라이트 차트 주간/월간 비교 조회 (Priority: P1)

사용자가 메인 대시보드에서 하이라이트 패널을 확인하여, 현재 주간(또는 월간)의 활동 데이터를 이전 주간(또는 월간)과 비교하여 막대 차트로 시각적으로 확인할 수 있다.

**Why this priority**: 하이라이트 패널의 핵심 기능이며, 사용자에게 가장 먼저 보여지는 데이터 비교 시각화이다.

**Independent Test**: 메인 페이지 진입 후 하이라이트 패널에서 주간 토글 선택 시 이번 주/저번 주 비교 막대 차트가 정상적으로 렌더링되는지 확인. API 응답 데이터가 차트에 올바르게 매핑되는지 검증.

**Acceptance Scenarios**:

1. **Given** 사용자가 메인 대시보드에 접속한 상태, **When** 하이라이트 패널이 로드되면, **Then** 기본값으로 주간 모드가 선택되고 이번 주와 저번 주의 비교 막대 차트가 표시된다.
2. **Given** 하이라이트 패널이 주간 모드로 표시 중, **When** 사용자가 월간 토글을 선택하면, **Then** 이번 달과 저번 달의 비교 막대 차트로 전환된다.
3. **Given** 하이라이트 패널이 월간 모드로 표시 중, **When** 사용자가 주간 토글을 선택하면, **Then** 주간 모드 차트로 전환된다.

---

### User Story 2 - API 데이터 연동 및 로딩 상태 처리 (Priority: P2)

하이라이트 패널이 백엔드 API에서 데이터를 조회하여 차트에 반영하며, 데이터 로딩 중이거나 API 오류 발생 시 적절한 대체 UI를 표시한다.

**Why this priority**: 실제 데이터 연동이 없으면 패널이 무의미하며, 로딩 및 에러 상태 처리는 안정적인 사용자 경험을 위해 필수적이다.

**Independent Test**: 네트워크 탭에서 API 호출이 정상적으로 발생하는지 확인. 느린 네트워크 환경에서 로딩 상태 UI가 표시되는지, 서버 오류 시 에러 처리가 되는지 검증.

**Acceptance Scenarios**:

1. **Given** API 서버가 정상 응답하는 상태, **When** 하이라이트 패널이 마운트되면, **Then** API 요청이 전송되고 응답 데이터가 차트에 반영된다.
2. **Given** API 요청이 진행 중인 상태, **When** 데이터가 아직 도착하지 않았으면, **Then** 로딩 인디케이터가 표시된다.
3. **Given** API 서버가 오류를 반환하는 상태, **When** 요청이 실패하면, **Then** TanStack Query의 retry 1회 재시도 후에도 실패 시 기본값(value=0)이 표시된다. 별도의 에러 메시지 UI는 표시하지 않고 빈 차트로 폴백한다.

---

### User Story 3 - 다크/라이트 테마 대응 (Priority: P3)

하이라이트 패널의 차트 색상, 라벨, 배경이 사용자의 테마 설정(다크/라이트)에 따라 일관되게 변경된다.

**Why this priority**: 기존 레거시에서 지원하던 기능이므로 동등한 사용자 경험을 보장하기 위해 필요하다.

**Independent Test**: 설정에서 테마를 전환할 때마다 하이라이트 패널의 차트 색상이 CSS 변수에 맞게 즉시 변경되는지 확인.

**Acceptance Scenarios**:

1. **Given** 시스템이 라이트 테마인 상태, **When** 하이라이트 패널이 렌더링되면, **Then** 라이트 테마 색상 체계로 차트가 표시된다.
2. **Given** 시스템이 다크 테마인 상태, **When** 사용자가 테마를 변경하면, **Then** 차트 색상이 다크 테마 색상 체계로 즉시 전환된다.

---

### Edge Cases

- API 응답 데이터에서 current 또는 previous 값이 0인 경우 → 레거시와 동일하게 value=0으로 막대가 표시되며 Y축은 기본 도메인(최대 100)으로 렌더링된다.
- 주간/월간 토글을 빠르게 반복 전환할 때 → TanStack Query의 캐시(staleTime 5분)로 중복 API 요청이 방지된다.
- 월간 모드에서 연도가 바뀌는 시점(예: 1월)에 이전 달 데이터 조회 → 레거시와 동일하게 현재 연도/월 기준으로 API 파라미터가 자동 계산된다.
- 데이터가 매우 큰 값(예: 1000분 이상)일 때 → Y축 도메인이 최대값+40 후 100 단위 올림으로 자동 조정된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사용자가 대시보드에서 하이라이트 패널을 볼 수 있어야 한다. 패널 헤더에 "하이라이트" 제목이 표시된다.
- **FR-002**: 시스템은 주간/월간 전환 토글 스위치를 제공해야 하며, 기본값은 주간 모드이다.
- **FR-003**: 시스템은 선택된 기간(주간/월간)에 따라 백엔드 API에서 현재 기간과 이전 기간의 비교 데이터를 조회해야 한다.
- **FR-004**: 시스템은 조회된 데이터를 막대 차트로 시각화해야 한다. 현재 기간과 이전 기간이 서로 다른 색상으로 구분된다.
- **FR-005**: 막대 차트의 각 막대 내부에 수치 라벨이 표시되어야 한다.
- **FR-006**: 차트에 "단위: 분/일" 라벨이 표시되어야 한다.
- **FR-007**: 시스템은 데이터 로딩 중 로딩 상태를 표시해야 한다.
- **FR-008**: 시스템은 사용자의 테마 설정(다크/라이트)에 따라 차트 색상을 동적으로 변경해야 한다.
- **FR-009**: UI 스타일(레이아웃, 색상, 간격, 폰트 크기 등)은 기존 레거시와 동일하게 유지되어야 한다.
- **FR-010**: 시스템은 기존 레거시와 동일한 API 엔드포인트(GET /dashboard/highlight)를 사용하여 데이터를 조회해야 한다.

### Key Entities

- **HighlightPeriod**: API 레벨 조회 기간 구분 (주간 WEEKLY / 월간 MONTHLY). 마이그레이션 프로젝트의 기존 `Period` 타입('WEEKLY' | 'MONTHLY')과 동일한 값으로, API 요청 시 사용된다.
- **HighlightData**: API 응답 데이터 — 현재 기간 수치(current), 이전 기간 수치(previous)
- **HighlightDatum**: 차트 표시용 데이터 — 기간 라벨(periodLabel), 수치(value), 현재/이전 구분(barKey: 'previous' | 'current'). API의 HighlightData를 차트 렌더링 형식으로 변환한 구조.
- **HighlightResponse**: API 응답 래퍼 — HighlightData를 data 필드로 포함

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 메인 대시보드 진입 시 하이라이트 패널이 다른 패널들과 함께 1초 이내에 렌더링된다.
- **SC-002**: 주간/월간 토글 전환 시 차트 데이터가 갱신되어 시각적으로 확인 가능하다.
- **SC-003**: 레거시 앱의 하이라이트 패널과 마이그레이션 앱의 하이라이트 패널을 나란히 비교했을 때 시각적 차이가 없다.
- **SC-004**: 다크/라이트 테마 전환 시 차트 색상이 즉시(1초 이내) 반영된다.

## Assumptions

- 기존 레거시에서 사용하는 API 엔드포인트(GET /dashboard/highlight)와 응답 형식은 변경되지 않는다.
- 기존 레거시의 TanStack Query 설정(staleTime 5분, retry 1회)을 그대로 적용한다.
- 차트 라이브러리는 기존과 동일한 Recharts를 사용하여 UI 일관성을 유지한다.
- 패널 헤더(PannelHeader)와 토글 스위치(ToggleSwitch) 공유 컴포넌트는 마이그레이션 프로젝트에 이미 존재하는 것을 사용한다.
- 메인 페이지 레이아웃 내 하이라이트 패널의 위치와 크기는 기존 레거시와 동일하게 유지한다.
- 인증 토큰(accessToken)은 기존 마이그레이션 프로젝트의 인증 체계를 따른다.
